# 重置预测方法与边界

## 事件类型

`hint` 为讨论或模糊承诺，`announced` 为带绝对时间的预告，`confirmed` 为已发生的记录，`banked` 为赠送重置次数，`incident` 为故障背景。只有 `confirmed + scope=all + 非 demo` 进入本地统计。

同一轮发布可能有多条帖子。发生时间相隔不超过 12 小时的记录被合并为一个事件。此规则可能合并真实的短间隔重置，属于保守的去重取舍。

`occurredAt` 是事件时间，`knownAt` 是本地首次获得当前证据的时间。更新分类或范围时重新记录认知时间。预测只使用截至预测时已发生且已获得的事件；不将后来获知的证据倒填进过去。

X 自动分类采用确定性规则。负面措辞与 banked reset 优先排除；只有明确的完成措辞才标为重置记录。相对时间（如 tomorrow、soon）保持为 hint，不凭发布日期或时区猜具体时刻。自动分类仍可能误判，用户应核对原帖；确认措辞而范围不明的帖子不进入全体重置模型。

## 条件经验分布

设历史相邻事件间隔为 `g`，距最近事件已等待 `a` 天，要预测未来 `h` 天发生事件的概率。只选择 `g > a` 的历史间隔，统计其中 `g ≤ a+h` 的数量 `k`，条件样本数为 `n`：

```text
P(reset within h | no reset through a) = (k + 2) / (n + 4)
```

使用 Beta(2,2) 平滑，避免小样本出现 0% / 100% 的假确定性。至少 10 个历史间隔且当前条件样本不少于 5，才展示 24h、72h、7d 的实验估计；否则返回 null。

这不是已经校准的概率模型。当前间隔的右删失没有作为额外完成事件计入；长尾等待导致条件样本太少时，直接停止给出估计。数据收集偏差、事件范围、重复记录和政策变化均会影响结果。

明确公告单独呈现时间与链接，不把公告伪装成“100% 预测”。本地概率不参与执行预算。可选的社区预测也独立显示，数据超过一小时或格式异常时拒绝更新，不参与任务准入。

## 消耗速度

只使用同源、同账号、同套餐、同窗口和同重置时间的最近六小时样本。相邻读取间隔超过 30 分钟、额度恢复或账号/套餐切换都会开始新片段。至少 3 次读数、跨度 10 分钟且消耗增加，才计算额度百分点每小时与预计耗尽时间。

这些趋势是账号级观测，不是 token 到额度的固定映射，不代表单任务成本。预计耗尽时间随着未来任务变化可能失效。

## 后续验证路线

未来版本应固定时间保存预测快照，保留当时可获得的证据与模型版本，等窗口成熟后计算 Brier score、校准曲线和相对于简单周期基线的增益。调度策略需要另测任务验收率、按时完成率和中断恢复成本。本版不提供未验证的准确率或节省比例。
